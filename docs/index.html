Architecture

双层结构

第一层负责把业务真的做出来，第二层负责把项目讲漂亮、讲清楚、讲成一个团队。

真实业务层

主系统

客户经理 Agent

抽取排位、科类、家庭情况、偏好，缺信息就先追问。

数据侦察 Agent

按排位和科类筛出冲稳保候选池，控制业务搜索空间。

策略 Agent

执行 Ban/Pick，优先考虑就业兑现率、城市机会和现实约束。

规则校验 Agent

做去重、拦截和自动补位，避免推荐结果看着漂亮但不可执行。

展示层

讲解视图

产品经理

解释为什么需要这套流程，而不是让模型直接算一个答案。

程序员

解释数据、脚本、OpenClaw 和输出报告是怎么串成闭环的。

测试

解释如何验证缺字段、风险专业、冲突推荐和边界场景。

Command Center

浏览器版模拟器

这是一套为 GitHub 展示页准备的前端模拟器，会在浏览器里重放自动工作流、人工专家补充判断卡片、老板驾驶舱和内部审计摘要。

可见闭环

微信侧会走同一条 `gaokao_workflow` 主链路，这个页面是它的 GitHub 展示版镜像。你在这里看到的自动结果、补充判断和审计摘要，会和本地脚本保持同样的边界口径。
