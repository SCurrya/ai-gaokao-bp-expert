# AI Gaokao BP Expert Agent / Role 对照表

## 1. 一句话先说清

这个项目采用“双层结构”：

- 第一层是主链路 Agent，负责真的把高考志愿分析做出来
- 第二层是展示层 Role，负责把系统设计、工程实现和质量验证讲清楚

---

## 3. 为什么前四个是真 Agent

### 客户经理 Agent

它不是单纯“换个语气问问题”，而是要完成独立任务：

- 判断信息是否完整
- 主动追问缺失字段
- 维护用户画像状态
- 决定何时把画像交给下游

所以它有独立目标、独立状态、独立输出，属于真 Agent。

### 数据侦察 Agent

它负责做数据检索与候选筛选：

- 读取本地院校数据
- 按排位和科类过滤
- 给出冲稳保候选池

它的职责非常明确，不只是解释问题，所以也是真 Agent。

### 策略 Agent

它负责真正的 Ban / Pick 决策：

- Ban 掉不适合的专业
- Pick 出冲稳保方案
- 给出现实主义原因

这是整个系统的核心智能单元。

### 规则校验 Agent

它负责最终把关：

- 检查规则冲突
- 检查输出是否完整
- 检查是否缺少风险提示

它承担独立质量责任，所以也应该建成真 Agent。

---

## 4. 为什么后面三个更适合先做 Role

### 产品经理

它更像“解释视角”：

- 为什么要先采集信息
- 为什么要做 Ban / Pick
- 为什么系统不能只靠一个大模型一次说完

它主要服务展示和讲解，不必先做成独立 Agent。

### 程序员

它更像“工程讲解视角”：

- 数据怎么流动
- Prompt 怎么组织
- OpenClaw 和脚本怎么串起来

当前更适合作为展示层角色。

### 测试

它现在主要是：

- 解释如何做边界验证
- 展示极端输入怎么测
- 说明质量保障意识

后面如果它开始自动构造测试样例、自动验输出，就可以升级成 QA Agent。

---

## 5. 这张对照表的作用

这张表的作用，是把真实业务 Agent 和展示型 Role 的边界区分清楚，避免把讲解视角误认为真实执行单元。

---

## 6. 当前最该优先实现的顺序

1. 规则校验 Agent
2. 客户经理 Agent 的多轮状态记忆
3. 产品经理 Role 展示视图
4. 测试 Role 展示视图

原因很简单：

- 数据侦察、策略脚本和客户经理入口都已经有基础
- 现在最缺的是“出口校验”和“多轮状态延续”
- 这两块补上，主系统就会明显像一个真的 Agent 产品
